Documento de Requisitos Técnicos

Requisitos elicitados a partir da análise das telas do frontend do Projeto I (arquivo docs/requisitos.md).

ID Funcionalidade Frontend Requisito Técnico Derivado (Backend) Tipo Prioridade
RF-01 Acompanhamento de status / homologação Endpoint GET /api/v1/pedidos/{id}/status retornando status atual, etapas concluídas, etapa em andamento e previsão. RF Alta
RF-02 Simulador de economia mensal e anual Endpoint POST /api/v1/simulacoes recebendo valor da fatura e retornando estimativa e memória de cálculo. RF Alta
RF-03 Área de Benefícios com parceiros Endpoints GET /api/v1/beneficios e POST /resgates para consulta e resgate de cupons parceiros. RF Média
RF-04 Dicas contextuais do mascote Bulbinho Endpoint GET /api/v1/ajuda/dicas servindo textos contextuais tipados sem necessidade de nova versão do app. RF Média
RNF-01 Acessibilidade por Design (WCAG) Interface compatível com leitores de tela e teclado; payloads carregam rótulos textuais acessíveis para cada valor. RNF Alta
RNF-02 Desempenho e resposta rápida Tempo de resposta da API abaixo de 400ms em consultas de status e simulação para conter ansiedade do usuário. RNF Alta
RNF-03 Segurança e Conformidade LGPD Tráfego criptografado via HTTPS/TLS, autenticação JWT e armazenamento seguro de dados de faturas conforme a LGPD. RNF Alta

Implementação FastAPI & Contrato OpenAPI

Separação rigorosa de responsabilidades em 4 camadas e documentação interativa corporativa.

ARQUITETURA DE SOFTWARE (app/)

4 Camadas Desacopladas

1. Controller: Mapeia rotas HTTP, parâmetros e status codes (200, 201, 204).

2. Service: Lógica de negócio, desconto de 15% e lançamento de ErroDeNegocio.

3. Models: Schemas Pydantic com validação rigorosa de contratos.

4. Repository: Acesso à persistência (retorna None, desacoplado de HTTP).
